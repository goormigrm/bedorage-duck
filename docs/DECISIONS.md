## 0. 지금 상태 솔직한 평가

| 항목 | 현재 | 문제 |
|---|---|---|
| 렌더러 | Canvas 2D 자체 구현 | "쿼터뷰"라고 한 것은 화면 y축을 0.72로 압축하고 벽을 34px 위로 돌출시킨 **가짜 투영**이다. 원근·조명·입체 캐릭터가 없어 결국 탑다운 2D로 보인다. |
| 덕코프 유사도 | 낮음 | 덕코프는 유니티 **3D** 게임이다. 기울인 원근 카메라, 로우폴리 3D 모델, 실시간 조명·그림자, 입체 벽. 우리 화면은 그 계열이 아니다. |
| 캐릭터 | 머리·몸·무기를 따로 그린 2D 부품 | 팔이 없고 무기가 몸 옆에 떠 있다. 걷기는 몸 바운스뿐. 얼굴 캐리커처는 사용자 승인 상태(철면·침착·단군·매직·주펄). |
| 유지 가치 있는 것 | 결정론 시뮬레이션, 봇 AI, 락스텝·방 코드 네트워크, 로비, 배포 파이프라인 | **모두 렌더러와 독립**이라 어떤 방향을 택해도 그대로 쓴다. 얼굴 드로잉 코드도 3D에서 텍스처로 재사용 가능. |

결론: 시각 계층만 갈아끼우면 되는 구조다. 갈아끼울 대상을 정해야 한다.

## 2. B안(Three.js) 을 고르면 이렇게 만든다

- **카메라**: 원근 카메라, 피치 약 55°, 요 0° (덕코프처럼 위에서 비스듬히 내려다봄), 플레이어 추적. 정조준 시 조준 방향으로 오프셋.
- **월드**: 지금의 32px 타일 그리드를 그대로 3D 로 올린다. 벽 = 캐릭터 키 1.2배 높이의 박스 메쉬, 바닥 = 평면 + 타일 텍스처, 소품(책상·소파·촬영장비) = 박스 조합. 방향광 + 그림자맵 + 앰비언트.
- **캐릭터 (치비 3D)**: 머리 = 둥근 박스 또는 구, **얼굴은 지금의 캔버스 캐리커처를 텍스처로 붙인다** (승인된 얼굴을 그대로 유지). 몸통 박스, 팔 2개는 총을 두 손으로 쥔 자세로 하나의 그룹 → 상체와 함께 조준 방향으로 회전. 다리 2개는 걷기 스윙. 모자·안경·머리카락·마이크는 작은 메쉬. 피격 시 스쿼시·플래시, 사망 시 넘어짐.
- **이펙트**: 총구 화염(점광 + 스프라이트), 탄 = 발광 캡슐, 피격 파티클, 탄피, 바닥 데칼.
- **HUD**: 지금 것을 DOM/캔버스 오버레이로 유지.
- **결정론**: 시뮬레이션 코드는 한 줄도 안 바꾼다. 렌더는 prev/curr 보간만.
- **성능**: 로우폴리 수백 삼각형 수준이라 노트북 내장 GPU 에서도 60fps.
- **리스크**: 3D 몸체는 단순화되므로 "닮음"은 얼굴 텍스처가 담당한다. 몸 실루엣(덩치·대두·단신)은 스케일로 표현.
