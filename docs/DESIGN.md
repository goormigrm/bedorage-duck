# 배도라지 덕 — 설계서 (v1.0)

> 배도라지 크루 12명을 둥글둥글한 캐릭터로 만든 **2~4인 쿼터뷰 슈터**.
> 게임 서버 없이 브라우저끼리 WebRTC 로 대전하고, GitHub Pages 에 정적 배포한다.
> 이 문서는 **현재 구현된 그대로**를 적는다. 변경 이력은 [CHANGELOG.md](../CHANGELOG.md), 작업 상태는 [HANDOVER.md](../HANDOVER.md).
> v1.0 기준일 2026-09-04. (v0.1~v0.4 초안은 git 이력에 남아 있다)

---

## 1. 정체성

- **장르**: 비스듬히 내려다보는 3D 쿼터뷰 슈터. Escape from Duckov 의 손맛(시야 제한·엄폐·부위 피해)을 2~4인 대전으로 압축.
- **한 판**: 3~6분. 방에 모여 준비 → 목표 킬 선취 → 결과 → 리매치.
- **조작**: 키보드 + 마우스. 모바일은 **가로 화면 전용** 터치 조작(왼쪽 이동 스틱 + 오른쪽 사격, **조준은 자동**).
- **원칙**: 설치 없음, 계정 없음, 서버 없음, 비용 없음.

## 3. 전투 시스템

### 3.1 체력과 기력

- 체력은 캐릭터마다 185~290. 총으로 여러 발 주고받아야 죽는다.
- **기력**(스테미나) 0~100, 초당 22 회복(근접 무기 2.4배).
  - **대시 34 소모**. 기력이 모자라면 구르지 못한다.
  - **근접 무기(후라이팬)를 든 사람은 앞쪽(±75°)에서 오는 총알을 기력으로 막는다.** 피해 1당 기력 0.55 — 기력 한 통으로 **피해 181**까지 막고, 떨어지면 그대로 맞는다.
  - **막은 직후 0.5초는 기력이 차지 않는다**(`BLOCK_LOCK_TICKS`). 그래서 계속 쏘면 방어가 결국 뚫린다.
    이 잠금이 없던 때에는 맞으면서도 기력이 차서, 서서 막기만 해도 총알을 무한히 튕겨 냈다(사람이 쓰면 사실상 무적).
    머리 판정은 막지 못하게 하는 안도 재 봤지만, 사람이든 봇이든 상대 한가운데를 겨누므로 명중 대부분이 머리 판정이라 방어가 아예 무의미해져서 넣지 않았다.
    `tools/melee.ts` 가 "구르지 않고 정면으로 버티는" 최악의 상황을 재현한다 — 10판 중 2~4판 이기는 정도가 적당하다.

### 3.2 대시 = 구르기

`Space` + 이동 방향. 10틱(주우재덕 13틱) 동안 빠르게 굴러가고, **구르는 동안은 맞지 않는다**. 화면에서도 몸이 한 바퀴 구른다.

### 3.3 부위 판정 (확률이 아니라 정확도)

탄 궤적(직선)과 상대 중심 사이의 거리 `d`, 상대 반지름 `r = 14px`:

| 조건 | 부위 | 배율 |
|---|---|---|
| `d ≤ 0.28r` | 머리 | ×2.0 (산탄 ×1.5) |
| `d ≤ 0.72r` | 몸통 | ×1.0 |
| 그 밖 | 다리 | ×0.6 + 3초간 이동 30% 감소 |

정중앙을 정확히 지나야 헤드샷이다. 조준이 곧 실력이 되고, 정조준(우클릭)으로 탄퍼짐을 줄이면 헤드샷 확률이 올라간다.

### 3.4 무기

모든 무기는 **꾹 누르면 연사**되고 탄이 떨어지면 자동 재장전된다. DPS 는 이론상 최대치(모두 명중 가정).

| 무기 | 피해 | 연사(틱) | 탄창 | 재장전 | 지향/조준 퍼짐 | 거리 감쇠 | DPS |
|---|---|---|---|---|---|---|---|
| 권총 | 27 | 11 | 14 | 1.5s | 4.9° / 1.8° | 없음 | 147 |
| SMG | 16 | 5 | 32 | 1.8s | 8.1° / 4.2° | 320~700px → 62% | 192 |
| 소총 | 23 | 10 | 30 | 2.2s | 6.3° / 1.4° | 420~820px → 78% | 138 |
| 산탄총 | 17 ×7 | 38 | 6 | 2.5s | 7.4° / 4.9° | 200~500px → 35% | 188 |
| 저격총 | 112 | 78 | 5 | 4.3s | **15.1°** / 0.4° | 없음 | 86 |
| 기관총 | 16 | 5 | 80 | 3.5s | 8.1° / 4.6° | 320~760px → 55% | 192 |
| 후라이팬 | 80 (근접 70px, ±60°) | 23 | 무한 | - | - | 없음 | 209 |

**밸런스 원칙**: 저격총만 한 방(몸 112, 머리 224)에 죽일 수 있다. 나머지는 한 번의 사격으로 절대 죽지 않는다 — `tests/determinism.test.ts` 가 강제한다. 저격총은 정조준 없이는 15° 로 퍼져 거의 맞지 않는다.

### 3.5 엄폐물 — 모래주머니

맵 가운데에 사방에서 드나들 수 있는 진지(8칸)가 하나 생기고, 곳곳에 짧은 줄이 몇 개 흩어진다. 4배 맵이면 진지가 하나 더 생긴다. **너무 많으면 어디서나 엄폐가 되어 규칙이 싱거워지므로 적게 둔다** — 기본 맵 기준 12~15칸.

- 이동을 막는다. **시야는 넘어간다**(허리 높이).
- 탄은 막힌다. 단, 두 경우는 **넘어간다**:
  1. 쏘는 사람이 모래주머니에 붙어 있을 때(46px 이내, "엄폐 중") — 뒤에 자리를 잡으면 일방적으로 때릴 수 있다.
  2. 그 탄이 상대의 **머리를 정확히 겨눈** 탄일 때 — 엄폐해도 헤드샷은 넘어온다.
- 내구도 240. 계속 맞으면 부서지고 지나갈 수 있게 된다.

겉모습은 자루를 **3 - 2 - 3 세 단**으로 쌓은 더미다(가운데 단은 이음매가 어긋나게 반 자루씩 밀었다). 바닥에 딱 붙여 놓고, 내구도가 닳으면 색이 점점 어두워진다.

|---|---|---|---|---|---|---|
| 철면덕 | 철면수심 | 기관총 | 290 | 2.8 | 1.8s | **차돌** 최대 체력 290 |

| 통닭덕 | 통닭천사 | 저격총 | 220 | 2.9 | 1.7s | **치킨** 킬 시 체력 50 회복 |

외형은 실제 인물의 참고 사진을 캐리커처로 옮긴 것이며, `characters.ts` 의 `look` 데이터로만 정의된다. 새 멤버 추가는 `look` 한 줄 + (필요하면) 머리 모양 케이스 하나.

**키**는 `look.tall`, **몸 폭**은 `look.slim` 이 정한다(둘 다 보기용이며 판정에는 영향이 없다 — 히트박스는 2D 원 하나다).
위에서 내려다보는 시점이라 몸통만 늘려서는 키 차이가 잘 안 보인다. 그래서 `tall` 은 **다리 길이도 같이 늘린다**(`legStretch = 1 + (tall-1) × 2.2`).
다리가 길면 몸이 그림자에서 멀어지고 걸음도 크게 젓기 때문에(`rig.stride`) 위에서 봐도 키가 읽힌다.
화면상 머리끝 높이는 주우재덕 82px, 풍월덕 39px (1280×720 기준).
실제 인물 기준의 키 순서를 그대로 따른다:

> 주우재덕 > 기열덕 > 침착덕 > 우원덕 > 매직덕 > (철면덕 = 승빠덕 = 주펄덕 = 옥냥덕) > 통닭덕 > (단군덕 = 풍월덕)

몸 크기(`headScale`·`bodyScale`)가 캐릭터마다 달라서, `tall` 은 "결과 키"가 위 순서가 되도록 맞춘 값이다. 값을 바꿀 때는 순서가 유지되는지 확인한다.

## 5. 맵

- **테두리와 크기만 고정**(`maps.ts` 의 문자 그리드), **안쪽 구조물은 매 판 시드로 생성**한다. 같은 시드면 모든 브라우저가 같은 맵을 만든다.
- 맵마다 뼈대 만드는 방식이 다르다: **rooms**(영역을 재귀로 갈라 방과 3칸 문을 만든다) · **scatter**(벽 덩어리를 흩뿌린다) · **pillars**(기둥을 격자로 세운다). 그 위에 상자 군집, 모래주머니 진지·줄을 올리고, 마지막에 갇힌 바닥이 없도록 벽을 뚫어 잇는다.
- 타일: 바닥 / 벽(높음, 시야 차단) / 상자(낮음, 탄만 차단) / 모래주머니(낮음, 파괴 가능).
- 스폰: 3×3 이 트인 칸 중 서로 가장 멀리 떨어진 곳을 최대 10곳.
- **인원별 확장**: 2명 원본, 3명 가로 2배, 4명 가로·세로 4배. 테두리 한 줄을 빼고 거울로 붙여 이음새가 통로가 된다.
- 맵 3종: **스튜디오**(실내, 방과 복도) · **마당**(야외, 트인 시야) · **주차장**(기둥 격자, 숨었다 나오는 싸움).

## 6. 시야 (전장의 안개)

- 내(그리고 아군) 위치에서 360방향으로 벽까지 레이캐스트한 다각형 ∩ 반경 13타일(416px).
- 그 밖의 바닥·벽 윗면·옆면을 어둡게 덮고, **시야 밖의 적은 아예 그리지 않는다**. 탄·이펙트는 보인다(총성이 나는 곳은 알 수 있다).
- 경계에서 깜빡이지 않도록 시야에서 벗어나도 0.22초는 유지한다.
- **저격 조준경**: 저격총 우클릭 시 화면이 어두워지고 **구멍이 두 개** 뚫린다 — 커서 둘레(십자선 포함)와 **내 주변**. 뒤쪽 구멍이 없으면 붙는 상대를 못 봐서 조준경이 자살행위가 된다.
  카메라는 1.45배 멀어지고 조준 방향으로 5타일 밀리며, 시야 반경은 1.8배가 된다. 미는 거리와 카메라 추종 속도를 낮게 잡아 둔 이유는, 조준경에서 조준선이 화면을 빨리 훑으면 맞히기가 급격히 어려워지기 때문이다.
- 렌더 전용이다. sim 은 모든 것을 알고 있으므로 치트 방지 효과는 없다(P2P 의 근본 한계).

## 7. 렌더링

- **Three.js**. 카메라는 원근 투영, **피치 55° · 요 45° 고정**(맵이 대각선으로 보여 상하 시야 차이가 줄어든다). WASD 는 화면 기준이고 내부에서 월드 8방향으로 변환한다.
- **캐릭터**: 머리와 몸이 하나인 달걀형 몸통에 얼굴·옷을 한 장 텍스처로 그린다(2D 캐리커처를 구 UV 에 배치). 머리카락·모자·귀·마이크는 달걀 표면을 따라가는 캡 메쉬, 팔은 옆구리 캡슐, 다리는 바닥의 짧은 캡슐.
- **연출**: 걷기 뒤뚱, 구르기 회전, 사망 시 뒤로 넘어짐, 피격 흰 플래시(한 틱에 여러 발 맞아도 한 번만), 총구 화염·탄·파편·링.
- **HUD**(2D 캔버스 오버레이): 위 점수판, 왼쪽 위 미니맵, 왼쪽 아래 내 카드(체력·기력·탄약), 오른쪽 아래 상대 목록, 아래 조작 안내 띠. 터치 조작일 때는 오른쪽 아래가 버튼 자리라 상대 목록이 미니맵 밑으로 내려가고 조작 안내 띠는 감춘다.
  - 캐릭터 위에는 체력 바, 오른쪽에는 세로 기력 바.
  - **상대의 체력·탄약은 보이지 않는다.** 맞힌 직후 2.5초만 그 사람 머리 위 체력이 보인다.

### 7.1 모바일 터치 조작 (가로 전용)

폰에서 스틱 두 개를 정확히 미는 것은 무리라고 판단해, **이동만 손으로 하고 조준은 대신 해 준다.**

- 왼쪽 절반: 이동 스틱(손가락을 대는 자리에 생긴다) · 오른쪽 절반: 누르고 있으면 사격(사격 버튼도 같은 일)
- 오른쪽에 조준(정조준 토글) / 구르기 / 재장전 / 교체, 왼쪽 위에 메뉴
- 화면 위 64px 은 조작 영역에서 빼 둔다(소리·로비로 버튼 자리). 오른쪽 아래는 버튼이 차지하므로 HUD 의 '다른 사람 목록'은 미니맵 아래로 내려간다.
- 조작 영역만 `pointer-events: auto` 다. 루트가 이벤트를 먹으면 위에 뜬 창(로비로·다시 하기)이 안 눌린다.
- 창(메뉴·결과·캐릭터 선택)이 떠 있는 동안은 조작 자체를 감춘다.

**자동 조준**(`localInput.autoAim`) 규칙:

- 대상: 살아 있고, 같은 편이 아니고, **눈에 보이는**(시야 반경 안 + 벽에 가리지 않은) 적. 조준경을 켜면 반경 1.8배.
- 여럿이면 `거리 + 현재 조준각과의 차이 × 2.2` 가 가장 작은 쪽. 표적이 매 틱 바뀌지 않도록 지금 겨눈 쪽에 가산점을 준다.
- **즉시 겨누지 않는다.** 한 틱에 최대 16/1024(≈5.6°, 초당 약 340°)만 돌고, 남은 각도의 25% 씩 접근한다. 뒤에 있는 적을 잡으려면 반 바퀴 도는 시간이 걸린다.
- 적이 없으면 가는 쪽을 본다.
- 조준각은 다른 입력과 똑같이 `Input` 에 실려 나가므로 동기화·결정론에 영향이 없다. PC 조작은 건드리지 않는다.

## 8. 네트워크

### 8.1 구조

- **시그널링**: [Trystero](https://github.com/dmotz/trystero) + 공개 Nostr 릴레이. 내가 운영하는 서버는 없다.
- **공용 로비 방**: 접속자 전원이 들어가는 방. 호스트가 자기 방 정보를 2초마다 방송하고, 7초간 소식이 없으면 목록에서 지운다.
- **게임 방**: 코드(6자)로 만드는 풀 메시. 정원 4명. **호스트(플레이어 0)가 멤버 순서·준비·팀을 방송하는 것이 정본**이고, 정원 초과는 거절한다.

### 8.2 결정론적 락스텝

- 입력은 6바이트(`mx, my, aim, buttons, char`). 틱 `t` 에 샘플한 입력을 `t + delay`(2~6틱, RTT 로 결정)에 배정하고 최근 8틱을 함께 보내 손실을 흡수한다.
- 모두의 입력이 도착한 틱만 진행한다(스톨). 4인 기준 한 사람이 보내는 양은 초당 약 10KB.
- 60틱마다 상태 해시를 호스트에게 보내고, 어긋난 사람에게만 호스트가 상태 스냅샷을 보내 되돌린다(모래주머니 상태도 함께 복원).
- **이탈**: 호스트가 앞선 틱을 정해 알리고, 모두가 같은 틱에 그 사람을 제거한다. 호스트가 나가면 방이 끝난다.
- 틱 타이머는 **전용 Web Worker**. 탭이 뒤에 있어도 시뮬레이션은 계속 돈다(렌더만 멈춘다).

### 8.3 한계

- **치트 방지 불가.** 권위 서버가 없다. 친구 대전용.
- 가장 느린 회선에 모두가 맞춰진다(락스텝 특성).
- 대칭 NAT·회사망에서는 연결이 안 될 수 있다. **TURN 은 쓰지 않는다**(비용 원칙) → "폰 핫스팟으로 재시도" 안내가 최종.
- 공용 로비 방은 접속자 전원이 하나의 메시라, 동시 접속이 수십 명 규모가 되면 그쪽이 먼저 부담이 된다.

### 8.4 전적 기록 — 서버도 DB도 없이

락스텝이 결정적이라 **경기가 끝난 순간 방에 있던 모두가 완전히 같은 결과를 들고 있다.** 그래서 결과를 어디에 보관할 필요 없이, 각자 브라우저가 자기 것을 적어 두면 네 사람의 기록이 자동으로 일치한다.

- 저장 위치: `localStorage['bd.records.v1']`, 최근 50판. 판이 끝나면 `session.onOver()` 가 한 줄 쓴다.
- 남기는 것: 끝난 시각 · 모드(혼자/방 대전, 개인전/2v2) · 맵 · 목표 킬 · 닉네임 · 캐릭터 · 킬 · 데스 · 팀 · 중도 퇴장 여부.
- 보는 곳: 로비 아래 "최근 전적". 내 줄은 노랗게 표시한다.
- 남에게 보여 줄 때: 카드의 **복사** 버튼이 붙여 넣기용 글을 만든다(`formatRecord`). 이 글이 곧 "기록 공유" 수단이다.

**하지 않는 것 · 할 수 없는 것**

- 전체 순위표는 없다. 남의 기록까지 모으려면 저장할 곳(서버·DB)이 필요한데, [비용 원칙](#15-비용-원칙)에 따라 두지 않는다.
- 브라우저 저장소라 시크릿 모드·기기 변경·저장소 삭제로 사라진다. 게임에는 영향이 없다.
- 클라이언트가 쓰는 값이라 위조할 수 있다. 친구끼리 보는 기록이지 공식 전적이 아니다.
- 나중에 순위표가 꼭 필요해지면 Cloudflare Workers 무료 플랜(+KV) 정도가 유일한 후보다. 카드 등록이 필요한 서비스는 그때도 쓰지 않는다.

## 9. 소리

파일 없이 **Web Audio 로 절차 생성**한다(저작권 문제 없음).

- 효과음: 무기별 총성, 피격·헤드샷, 사망, 리스폰, 대시, 재장전, 벽 튐, 총알 막기, 모래주머니 파괴, 카운트다운, 시작·종료 화음. 듣는 위치 기준 거리 감쇠와 좌우 패닝.
- 배경음: 132 BPM 단조 추격 루프(킥·스네어·하이햇 + 16분 베이스 + 아르페지오 + 리드 + 8마디마다 상승음). 교전이 벌어지면 레이어가 두꺼워진다.
- `N` 키 또는 화면 오른쪽 위 버튼으로 음소거(브라우저에 기억).

## 10. 결정론 규칙 (반드시 지킬 것)

`src/core/` 는 두 브라우저가 같은 입력으로 **완전히 같은 결과**를 내야 한다.

1. `Math.sin/cos/atan2/random`, `Date.now`, `performance.now` 금지. 삼각함수는 `fixedmath.ts` 의 1024단계 테이블(1/65536 단위로 반올림), 난수는 `rng.ts`(mulberry32).
2. 렌더·DOM·오디오를 import 하지 않는다.
3. 플레이어의 의사(캐릭터 교체 등)는 반드시 `Input` 에 실어 보낸다. 렌더 쪽에서 직접 상태를 바꾸지 않는다.
4. 맵은 시드로 생성한다. 모래주머니가 부서지면 sim 이 `map.tiles` 를 바꾸지만, 정본은 `GameState.sandbags` 이고 `createState`/`syncSandbags` 로 언제나 복원된다.
5. 부동소수 연산 순서를 바꾸지 않는다(반복 순서도 상태의 일부다).

검증: `tests/determinism.test.ts` 가 같은 시드로 두 번 돌려 60틱마다의 해시를 비교한다.

## 11. 성능

`tests/perf.test.ts` 가 매번 측정한다(60Hz 예산은 틱당 16.6ms).

| 상황 | 틱당 |
|---|---|
| 4인 · 4배 맵 · 봇 4명 (혼자 하기 최악) | 0.023 ~ 0.033ms |
| 4인 대전 (봇 없음) | 0.001ms |
| 2인 기본 맵 · 봇 | 0.011 ~ 0.015ms |

(측정 PC 사정에 따라 흔들리므로 범위로 적는다. 테스트는 "예산의 몇 % 안"만 본다.)

시뮬레이션은 사실상 공짜다. 실제 비용은 렌더링(Three.js)과 시야 마스크이며, 시야 마스크 해상도는 맵 크기에 따라 자동으로 낮춘다.

## 12. 밸런스 방법론

`tools/balance.ts` 가 봇끼리 **1:1 전 조합 528판**과 **4인 개인전 72판**을 돌려 캐릭터별 승률·K/D·주고받은 피해, 무기별 명중률·헤드샷 비율·거리 구간별 명중을 표로 뽑는다.

```bash
npx vite-node tools/balance.ts       # 1:1 전 조합
npx vite-node tools/balance.ts ffa   # 4인 개인전
```

2026-09-05 기준 1:1 승률은 **42.0 ~ 56.8%** 밴드. `tests/balance.test.ts` 가 매 테스트마다 20~80% 밴드와 모든 무기의 유효성을 검사한다.

봇은 **의도적으로 막기를 유지하는 플레이를 못 한다.** 그래서 후라이팬처럼 사람이 쓸 때만 강한 것은 이 표에 안 잡힌다.
`tools/melee.ts` 가 그 구멍을 메운다 — 승빠덕이 구르지 않고 정면으로 버티는 최악의 대치를 10판 돌린다.

봇 실력은 사람과 다르므로 이 수치는 "어느 쪽이 크게 기울었는가"를 보는 용도다. 사람이 직접 해 본 체감이 최종 기준이다.

## 14. 빌드와 배포

```bash
npm run dev      # 개발 서버
npm test         # vitest (결정론·카메라·성능·밸런스)
npm run build    # tsc --noEmit + vite build → dist/
```

`main` 에 push 하면 GitHub Actions 가 테스트·빌드 후 GitHub Pages 에 배포한다(`.github/workflows/deploy.yml`).

진입점은 `index.html` 하나다(트레일러용 프리뷰 페이지는 v1.0 에서 삭제했다).
개발 서버에만 스크린샷 저장 엔드포인트 `POST /__shot` 이 있다(`vite.config.ts` 의 `shotEndpoint`, `apply: 'serve'`).
주소 뒤에 `?shot=1` 을 붙이면 WebGL 캔버스 버퍼가 보존되어 `canvas.gl` + `canvas.hud` 를 합쳐 저장할 수 있다. 배포물에는 없다.

## 15. 비용 원칙

**카드 등록이 필요한 서비스는 무료 티어라도 쓰지 않는다.** 사용량 초과 시 과금 가능성이 있으면 배제한다.

| 쓰는 것 | 쓰지 않는 것 |
|---|---|
| GitHub Pages, Google Fonts, 공개 Nostr 릴레이, 무료 STUN, (필요 시) Cloudflare Workers 무료 플랜 | TURN 서버 전부(metered.ca, Cloudflare Realtime, Twilio 등), 유료 CDN·백엔드 |

## 16. 법적 · 초상권

- 실명 대신 **패러디 명칭**(침착덕·철면덕 등)을 쓰고, 원본 활동명은 작게 병기한다.
- 첫 화면에 "비공식 팬 프로젝트 · 비상업 · 문의 시 즉시 삭제" 고지.
- 광고·후원·굿즈 없음. 멤버 비하로 읽힐 수 있는 요소를 넣지 않는다.
- Escape from Duckov(Team Soda)와도 무관하다. 장르적 참고일 뿐 에셋·코드를 쓰지 않았다.

## 17. 알려진 한계 · 하지 않기로 한 것

- 관전 모드, 매치메이킹, 계정 없음.
- **전체 순위표 없음.** 전적은 각자 브라우저에만 남는다([8.4](#84-전적-기록--서버도-db도-없이)).
- 탈출/루팅 모드(초안의 "탈출 결투")는 하지 않는다.
- 아머·인벤토리 없음. 무기는 캐릭터 고정.
- 브라우저 탭이 뒤에 있으면 화면이 멈춘다(시뮬은 Worker 로 계속 돈다).
- 모바일은 조준이 자동이라 PC 와 조준 감각이 다르다. 같은 방에서 섞여도 막지 않는다(팬게임이라 경쟁 공정성보다 접근성을 택했다).
- 트레일러용 프리뷰 페이지(`preview.html`)는 v1.0 에서 삭제했다. 다시 필요하면 실제 게임을 녹화한다.
