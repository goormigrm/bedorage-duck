# 배도라지 덕 — 설계서 (v1.5)

> 배도라지 크루 12명을 둥글둥글한 캐릭터로 만든 **2~4인 쿼터뷰 슈터**.
> 게임 서버 없이 브라우저끼리 WebRTC 로 대전하고, GitHub Pages 에 정적 배포한다.
> 이 문서는 **현재 구현된 그대로**를 적는다. 변경 이력은 [CHANGELOG.md](../CHANGELOG.md), 작업 상태는 [HANDOVER.md](../HANDOVER.md).
> v1.5 기준일 2026-09-06. (v0.1~v0.4 초안은 git 이력에 남아 있다)

---

## 1. 정체성

- **장르**: 비스듬히 내려다보는 3D 쿼터뷰 슈터. Escape from Duckov 의 손맛(시야 제한·엄폐·부위 피해)을 2~4인 대전으로 압축.
- **한 판**: 3~6분. 방에 모여 준비 → 목표 킬 선취 → 결과 → 리매치.
- **조작**: 키보드 + 마우스. 모바일은 **가로 화면 전용** 터치 조작(왼쪽 이동 스틱 + 오른쪽 사격, **조준은 자동**).
- **원칙**: 설치 없음, 계정 없음, 서버 없음, 비용 없음.

## 3. 전투 시스템

### 3.1 체력과 기력

- 체력은 캐릭터마다 185~290. 총으로 여러 발 주고받아야 죽는다.
- **힐팩**: 누가 죽으면 그 자리에 떨어진다(최대 체력 35% 회복, 20초 뒤 소멸, 한 번에 최대 6개).
  다친 사람만 줍고 체력이 가득이면 남는다. 동시에 밟으면 번호가 앞선 사람이 줍는다(양쪽 화면이 같아야 하므로).
  상자에서는 나오지 않는다 — **이긴 쪽이 그 자리를 차지해 이어서 싸우게** 하는 장치다.
- **기력**(스테미나) 0~100, 초당 22 회복(근접 무기 2.4배).
  - **대시 34 소모**. 기력이 모자라면 구르지 못한다.
  - **달리기 초당 30 소모**(3.5 참고). 달리는 동안에는 **차지 않는다**.
  - **근접 무기(후라이팬)를 든 사람은 앞쪽(±75°)에서 오는 총알을 절반 확률로 막는다**(`BLOCK_CHANCE = 0.5`). 막을 때 피해 1당 기력 0.55 — 기력 한 통으로 **피해 181**까지 막고, 떨어지면 그대로 맞는다.
    추첨은 sim 의 시드 난수라 두 브라우저에서 같은 결과가 난다.
  - **막은 직후 0.5초는 기력이 차지 않는다**(`BLOCK_LOCK_TICKS`). 그래서 계속 쏘면 방어가 결국 뚫린다.
    이 잠금이 없던 때에는 맞으면서도 기력이 차서, 서서 막기만 해도 총알을 무한히 튕겨 냈다(사람이 쓰면 사실상 무적).
    잠금만으로도 여전히 정면 대치가 세서 2026-09-06 에 **절반 확률**을 넣었다. 이제 서서 버티면 절반은 그대로 맞아, 기력이 바닥나기 전에 체력이 먼저 닳는다.
    머리 판정은 막지 못하게 하는 안도 재 봤지만, 사람이든 봇이든 상대 한가운데를 겨누므로 명중 대부분이 머리 판정이라 방어가 아예 무의미해져서 넣지 않았다.
    `tools/melee.ts` 가 "구르지 않고 정면으로 버티는" 최악의 상황을 재현한다. 승빠덕의 살길은 **굴러서 붙는 것**이고, 정면으로 버티면 진다.

### 3.2 대시 = 구르기

`Space` + 이동 방향. 10틱(우재덕 13틱) 동안 빠르게 굴러가고, **구르는 동안은 맞지 않는다**. 화면에서도 몸이 한 바퀴 구른다.

> 2026-09-06 이전에는 `Shift` 도 구르기였다. 지금 `Shift` 는 달리기다(3.2.1).

### 3.2.1 달리기 (Shift)

`Shift` 를 누르고 있는 동안 **이동 속도 1.4배**, 초당 기력 30 소모(`SPRINT_MUL` · `SPRINT_COST`).

- 움직이는 동안에만 든다. 제자리에서 누르고 있어도 기력이 줄지 않는다.
- **정조준(우클릭) 중에는 달리지 않는다.** 구르는 중에도 끼어들지 않는다(구르기 속도가 따로 있다).
- 쏘면서 달릴 수는 있다. 대가는 기력 하나뿐이라, "달릴까 굴러 둘까"를 계속 고르게 된다.
- 한 통이면 3.3초를 달린다. 바닥나면 **20 이 찰 때까지(약 0.9초) 다시 못 달린다**(`SPRINT_MIN`).
  이 문턱이 없으면 기력 0 에서 한 틱 회복 → 한 틱 달리기가 반복돼 사실상 무한히 달린다(회복 22 와 소모 30 이 비슷해서 그렇다).
- 폰은 **달리기 버튼**으로 켜고 끈다(2026-09-05). 전에는 스틱을 끝까지 밀면 달렸는데, 스틱은 늘 끝까지 밀리므로 무조건 달리는 꼴이었다.
- 봇도 달린다. 단 **교전 중에는 달리지 않고**, 기력이 75 넘게 남았을 때만 쓴다 — 구르기 몫을 남기지 않으면 회피를 못 해 눈에 띄게 약해진다.

### 3.3 부위 판정 (확률이 아니라 정확도)

> **머리가 크면 헤드샷을 더 맞는다**(2026-09-05 요청). 머리 판정 범위에 그 캐릭터의 머리 크기(`look.headScale`)를 곱한다.
> 다만 그대로 곱하면 매직덕(1.45)이 맞은 탄의 37.8% 를 머리로 맞아 승률이 20% 까지 떨어져, 차이를 절반쯤으로 눌렀다
> (`HEAD_SIZE_EFFECT = 0.6` → 매직덕 1.27 · 철면덕 1.12 · 우재덕 0.94). 커서가 상대 위인지 보는 범위와 조준선 금색도 같은 배율이라
> **보이는 머리 크기 = 판정 크기**다. 매직덕은 그 대신 체력을 235 → 255 로 올렸다.

> **2026-09-05: 헤드샷 = "쏠 때 커서가 그 상대 위"(조준선 금색) + 그 상대를 맞힘.** 입력에 **조준 거리**(`aimDist`, 4px 단위 1바이트)가
> 실려 조준점이 생기고, 조준점이 반지름의 `HEAD_AIM_FRAC`(0.5, 약 7px) 안에 있는 적이 `Bullet.headTarget` 이 된다.
> 처음엔 여기에 "궤적이 정중앙(0.28r)을 지나야" 도 붙어 있었는데, 탄퍼짐·반동 때문에 커서를 정확히 올리고 쏴도 몸통이 되곤 했다
> ("금색인데 헤드샷이 안 난다" 제보). 이제 **단발 무기는 커서가 상대 위였으면 맞기만 하면 머리**다 — 금색이면 헤드샷, 예외 없이.
> 산탄총만 예외로 커서가 상대 위여도 정중앙을 지나는 탄만 머리다(탄 7개가 전부 머리가 되면 과하다). 그 대신 범위를 0.7r → 0.5r 로 좁혔다.
> 모래주머니를 넘기는 "머리 조준" 관통은 정밀 조건(커서 위 + 궤적 정중앙)을 그대로 둔다 — 엄폐를 쉽게 뚫으면 안 된다.
> 봇도 조준점을 표적 위에 둔다. 그래도 헤드샷 빈도는 30% → 11~14% 로 준다 — 탄퍼짐으로 우연히 정중앙을 지나던 탄이 이제 머리로 안 쳐진다(사람도 같다). 입력 7바이트 → `APP_ID` v3.

탄 궤적(직선)과 상대 중심 사이의 거리 `d`, 상대 반지름 `r = 14px`:

| 조건 | 부위 | 배율 |
|---|---|---|
| `d ≤ 0.28r` | 머리 | ×2.0 (산탄 ×1.5) |
| `d ≤ 0.72r` | 몸통 | ×1.0 |
| 그 밖 | 다리 | ×0.6 + 3초간 이동 30% 감소 |

정중앙을 정확히 지나야 헤드샷이다. 조준이 곧 실력이 되고, 정조준(우클릭)으로 탄퍼짐을 줄이면 헤드샷 확률이 올라간다.

### 3.5 엄폐물 — 모래주머니

맵 가운데에 사방에서 드나들 수 있는 진지(8칸)가 하나 생기고, 곳곳에 짧은 줄이 몇 개 흩어진다. 4배 맵이면 진지가 하나 더 생긴다. **너무 많으면 어디서나 엄폐가 되어 규칙이 싱거워지므로 적게 둔다** — 기본 맵 기준 12~15칸.

- 이동을 막는다. **시야는 넘어간다**(허리 높이).
- 탄은 막힌다. 단, 두 경우는 **넘어간다**:
  1. 쏘는 사람이 모래주머니에 붙어 있을 때(**28px 이내**, "엄폐 중") — 뒤에 자리를 잡으면 일방적으로 때릴 수 있다.
     넘어가는 것은 **기대고 있는 그 자루뿐**이다(총구에서 COVER_DIST + 3칸까지). 그 너머의 다른 줄은 엄폐 중이어도 막는다.
  2. 그 탄이 상대의 **머리를 정확히 겨눈** 탄일 때 — 엄폐해도 헤드샷은 넘어온다. 이쪽은 거리 제한이 없다.

  > 2026-09-06 수정 전에는 기준이 46px 이라 **두 칸 떨어진 대각선**도 붙은 것으로 쳤고, 엄폐 중이면 맵의 **모든**
  > 모래주머니를 통과했다. 그래서 "멀찍이 서서 쐈는데 방향에 따라 탄이 그냥 넘어간다" 는 제보가 나왔다.
- 내구도 240. 계속 맞으면 부서지고 지나갈 수 있게 된다.

겉모습은 자루를 **3 - 2 - 3 세 단**으로 쌓은 더미다(가운데 단은 이음매가 어긋나게 반 자루씩 밀었다). 바닥에 딱 붙여 놓고, 내구도가 닳으면 색이 점점 어두워진다.

**탄속.** 권총 15 · SMG 14 · **소총 24**(2026-09-05 17 → 24, 사용자: 소총 밸런스. 빨라진 만큼 피해 23 → 20) · 산탄 14 · 저격 26 · 기관총 15 px/틱.
탄속이 빠를수록 움직이는 상대를 덜 예측해도 맞는다. 소총은 수명을 70 → 50 틱으로 줄여 사거리(약 1200px)는 그대로다.

외형은 실제 인물의 참고 사진을 캐리커처로 옮긴 것이며, `characters.ts` 의 `look` 데이터로만 정의된다. 새 멤버 추가는 `look` 한 줄 + (필요하면) 머리 모양 케이스 하나.

**키**는 `look.tall`, **몸 폭**은 `look.slim` 이 정한다(둘 다 보기용이며 판정에는 영향이 없다 — 히트박스는 2D 원 하나다).
위에서 내려다보는 시점이라 몸통만 늘려서는 키 차이가 잘 안 보인다. 그래서 `tall` 은 **다리 길이도 같이 늘린다**(`legStretch = 1 + (tall-1) × 2.2`).
다리가 길면 몸이 그림자에서 멀어지고 걸음도 크게 젓기 때문에(`rig.stride`) 위에서 봐도 키가 읽힌다.
화면상 머리끝 높이는 우재덕 82px, 풍월덕 39px (1280×720 기준).
실제 인물 기준의 키 순서를 그대로 따른다:

> 우재덕 > 기열덕 > 침착덕 > 우원덕 > 매직덕 > (철면덕 = 승빠덕 = 주펄덕 = 옥냥덕) > 통천덕 > (단군덕 = 풍월덕)

몸 크기(`headScale`·`bodyScale`)가 캐릭터마다 달라서, `tall` 은 "결과 키"가 위 순서가 되도록 맞춘 값이다. 값을 바꿀 때는 순서가 유지되는지 확인한다.

**머리 크기와 헤드샷.** 판정 배율은 `headHitScale(id)` = `1 + (headScale - 1) × 0.6`.

| 캐릭터 | 머리 | 판정 배율 | 맞은 탄 중 헤드샷 (머리 크기 그대로 → 0.6 완화) |
|---|---|---|---|
| 매직덕 | 1.45 | 1.27 | 37.8% → **30.1%** |
| 철면덕 | 1.20 | 1.12 | 20.2% → **16.3%** |
| 풍월덕 | 1.15 | 1.09 | 23.8% → **21.8%** |
| 우재덕 | 0.90 | 0.94 | 8.4% → **8.3%** |

체력이 두꺼운 캐릭터일수록 머리가 커서, "맞아 주는 대신 머리를 조심해야 한다" 가 성립한다.

## 5. 맵

- **테두리와 크기만 고정**(`maps.ts` 의 문자 그리드), **안쪽 구조물은 매 판 시드로 생성**한다. 같은 시드면 모든 브라우저가 같은 맵을 만든다.
- 맵마다 뼈대 만드는 방식이 다르다: **rooms**(영역을 재귀로 갈라 방과 3칸 문을 만든다) · **scatter**(벽 덩어리를 흩뿌린다) · **pillars**(기둥을 격자로 세운다). 그 위에 상자 군집, 모래주머니 진지·줄을 올린다.
- 마지막에 **통행을 세 단계로 보정**한다: 갇힌 바닥 잇기(`ensureConnected`) → 바로 옆인데 멀리 돌아가는 벽에 구멍 내기(`openShortcuts`) → 그래도 남는 먼 구간을 직선으로 잇기(`straightenPaths`).
  기준은 **우회도**(걷는 거리 / 직선 거리, 8방향): 평균 1.06~1.09, 최악 1.5 아래. 갇히는 곳은 없다.
- 타일: 바닥 / 벽(높음, 시야 차단) / 상자(낮음, 탄만 차단) / 모래주머니(낮음, 파괴 가능).
- 스폰: 3×3 이 트인 칸 중 서로 가장 멀리 떨어진 곳을 최대 10곳.
- **인원별 확장**: 2명 원본, 3명 가로 2배, 4명 가로·세로 4배. 테두리 한 줄을 빼고 거울로 붙여 이음새가 통로가 된다.
- 맵 3종: **스튜디오**(실내, 방과 복도) · **마당**(야외, 트인 시야) · **주차장**(기둥 격자, 숨었다 나오는 싸움).

## 6. 시야 (전장의 안개)

- 내(그리고 아군) 위치에서 360방향으로 벽까지 레이캐스트한 다각형 ∩ 반경 13타일(416px).
- 그 밖의 바닥·벽 윗면·옆면을 어둡게 덮고, **시야 밖의 적은 아예 그리지 않는다**. 탄·이펙트는 보인다(총성이 나는 곳은 알 수 있다).

- **저격 조준경**: 저격총 우클릭 시 화면이 어두워지고 **구멍이 두 개** 뚫린다 — 커서 둘레(십자선 포함)와 **내 주변**. 뒤쪽 구멍이 없으면 붙는 상대를 못 봐서 조준경이 자살행위가 된다.
  카메라는 1.45배 멀어지고 조준 방향으로 5타일 밀리며, 시야 반경은 1.8배가 된다. 미는 거리와 카메라 추종 속도를 낮게 잡아 둔 이유는, 조준경에서 조준선이 화면을 빨리 훑으면 맞히기가 급격히 어려워지기 때문이다.
- 렌더 전용이다. sim 은 모든 것을 알고 있으므로 치트 방지 효과는 없다(P2P 의 근본 한계).

### 7.-1 로비 화면 (2026-09-05 재구성)

### 7.-2 미니맵 (2026-09-05 재설계)

방향을 머리로 한 번 돌려야 했다. 지금은 월드 → 화면 회전(카메라 요)을 미니맵에도 똑같이 걸어, **미니맵의 위 = 화면의 위**다.
- 한 변 170px, 타일당 11px(한 변 ≈ 15칸, 대각선 ≈ 21칸). 창 밖은 그리지 않는다.
- 가운데는 나(관전 중이면 보고 있는 사람). 아군은 파랑, 보이는 적만 빨강, 나와 아군에게는 조준 방향 선.
- 터치 조작의 "다른 사람 목록" 은 미니맵 아래(y 204)로 내려간다.

### 7.0 죽었을 때 · 맞았을 때 · 팀 신호

- **관전**: 죽으면 카메라와 시야가 다른 사람에게 옮겨 간다(`A`/`D` 또는 `←`/`→` 로 전환, 리스폰하면 복귀).
  **개인전은 나를 죽인 사람**부터, **팀전은 아군만** 본다 — 팀전에서 상대 시점을 보여 주면 적 위치가 그대로 드러난다.
  렌더 옵션 `viewer` 가 카메라·시야만 바꾸고, HUD 의 내 카드는 그대로 나를 가리킨다. sim 은 건드리지 않는다.
- **피격 방향**: 맞으면 화면 가장자리에 쏜 쪽을 가리키는 호가 뜬다(큰 피해는 굵고 붉게). 각도는 화면 기준이라 보이는 대로 돌면 된다.
- **팀 신호**: 팀전에서 `V`(모바일은 신호 버튼)로 커서가 가리키는 지면에 마커를 찍는다. 같은 편만 보이고 6초 뒤 사라진다.
  컨트롤 메시지로 보내므로 **sim 밖**이다 — `Input` 을 키우지 않고 결정론 표면도 넓히지 않는다.

### 7.1 모바일 터치 조작 (가로 전용)

폰에서 스틱 두 개를 정확히 미는 것은 무리라고 판단해, **이동만 손으로 하고 조준은 대신 해 준다.**

- 왼쪽 절반: 이동 스틱(손가락을 대는 자리에 생긴다) · 오른쪽 절반: 누르고 있으면 사격(사격 버튼도 같은 일)
- 오른쪽에 조준(정조준 토글) / 구르기 / 재장전 / 교체 / **달리기(켜고 끄기)**, **오른쪽 위에 ≡ 메뉴**(소리·로비로가 그 안에 있다)
- 화면 위 64px 은 조작 영역에서 빼 둔다(≡ 자리). 오른쪽 아래는 버튼이 차지하므로 HUD 의 '다른 사람 목록'은 미니맵 아래로 내려간다.
- 조작 영역만 `pointer-events: auto` 다. 루트가 이벤트를 먹으면 위에 뜬 창(로비로·다시 하기)이 안 눌린다.
- 창(메뉴·결과·캐릭터 선택)이 떠 있는 동안은 조작 자체를 감춘다.

**자동 조준**(`localInput.autoAim`) 규칙:

- 대상: 살아 있고, 같은 편이 아니고, **눈에 보이는**(시야 반경 안 + 벽에 가리지 않은) 적. 조준경을 켜면 반경 1.8배.
- 여럿이면 `거리 + 현재 조준각과의 차이 × 2.2` 가 가장 작은 쪽. 표적이 매 틱 바뀌지 않도록 지금 겨눈 쪽에 가산점을 준다.
- **즉시 겨누지 않는다.** 한 틱에 최대 16/1024(≈5.6°, 초당 약 340°)만 돌고, 남은 각도의 25% 씩 접근한다. 뒤에 있는 적을 잡으려면 반 바퀴 도는 시간이 걸린다.
- 적이 없으면 가는 쪽을 본다.
- **일부러 못 맞힌다**(2026-09-05). 정확히 정중앙을 잡아 주니 폰에서 저격이 헤드샷 기계가 됐다. 봇의 손떨림과 같은 구조로
  0.4~0.8초마다 ±9° 안에서 치우침을 새로 뽑고, ±3° 사인파로 계속 흔든다(`AUTO_AIM_BIAS`·`AUTO_AIM_SWAY`). 어려움 봇(8° + 4.5°)보다 조금 더 크다.
- **조준선은 실제 자동 조준점에 그린다**(표적 위, 흔들림 포함). 폰에서 사람이 하는 건 이동과 사격뿐이라, 지금 어디를 겨누는지 보여야 한다.
  표적이 없으면 전처럼 바라보는 방향 190px 앞.
- 조준각·조준 거리는 다른 입력과 똑같이 `Input` 에 실려 나가므로 동기화·결정론에 영향이 없다. PC 조작은 건드리지 않는다.

### 7.2 결과 화면 통계

킬·데스에 더해 **연속 킬 · 명중률 · 헤드샷 비율 · 준 피해 · 받은 피해**를 표로 보여 준다.

- 수치는 전부 **sim 안에서** 센다(`PlayerState.shots/hits/heads/dmgDealt/dmgTaken/bestStreak`).
  렌더 계층에서 이벤트를 세면 리싱크·재접속에 값이 어긋나고 사람마다 다른 표를 보게 된다.
- **명중률은 탄 단위**다(`shots += weapon.pellets`). 방아쇠 횟수로 세면 산탄총 한 발(탄 7개)이 700% 처럼 보인다.
- 후라이팬에 막힌 탄은 피해가 0 이라 명중으로 세지 않는다.

## 8. 네트워크

### 8.-1 인원을 4로 둔 이유

6·8인도 계산(틱당 0.03ms)과 대역폭(22KB/s)은 여유다. 막는 것은 두 가지다.

- **풀 메시 연결 수**: 8인이면 28쌍이 전부 뚫려야 한다. TURN 없이 STUN 만 쓰므로 한 쌍만 실패해도 그 둘은 게임이 안 된다.
- **락스텝의 지터 전파**: 한 사람이 1틱을 놓칠 확률이 1% 여도 4인은 3.0%, 8인은 6.8% 로 전원이 멈춘다.

실제로 3인(한 명 무선) 테스트에서 이미 끊김이 체감됐다. **늘리려면 롤백 넷코드가 먼저다.**

### 8.0 게임 중 난입

방을 만들 때 **정원**(2~4)을 정하고, 둘만 모여도 시작한다. 남은 자리는 게임 중에 채워진다.

- 시작할 때 자리를 정원만큼 잡아 두고, 아직 아무도 없는 자리는 `left` 로 시작해 판에 나오지 않는다.
  배열 크기를 중간에 바꾸지 않으므로 결정론이 단순해진다.
- 호스트는 **게임 중에도 방을 방송한다**. 안 하면 시작하는 순간 목록에서 사라져 아무도 못 들어온다.
- 난입 절차는 재접속과 같다: 호스트가 빈 자리를 배정하고 앞선 틱 T 를 알린 뒤, T 에 그 자리를 채우고 판 전체를 보낸다.

### 8.0.1 나가면 · 혼자 남으면

- **나가면 3초 뒤 자리를 비운다.** 그동안 락스텝이 빈 입력을 채우므로 남은 사람들의 경기는 멈추지 않는다.
  비워진 자리는 난입으로 채워진다. **자동 재접속은 하지 않는다**(2026-09-06 제거 — 실제로 잘 되지 않았다).
- **팀전은 한 명만 나가도 그 자리에서 끝난다**(8.5). 난입도 없다.
- **혼자 남아도 30초는 방을 유지한다.** 화면에 카운트다운이 뜨고, 방은 계속 방송되어 목록에 "난입 가능" 으로 보인다.
  누가 들어오면 그대로 이어서 하고, 30초가 지나면 방을 닫는다.

### 8.1 구조

- **시그널링**: [Trystero](https://github.com/dmotz/trystero) + 공개 Nostr 릴레이. 내가 운영하는 서버는 없다.
- **초대 링크는 없다**(2026-09-05). 방에 들어가는 길은 **방 목록뿐**이고 주소에 방 코드를 남기지 않는다 — 사이트 안에서만 함께한다(사용자).
- **공용 로비 방**: 접속자 전원이 들어가는 방. 호스트가 자기 방 정보를 2초마다 방송하고, 7초간 소식이 없으면 목록에서 지운다.
- **게임 방**: 코드(6자)로 만드는 풀 메시. 정원 4명. **호스트(플레이어 0)가 멤버 순서·준비·팀을 방송하는 것이 정본**이고, 정원 초과는 거절한다.
  코드는 **내부 식별자와 초대 링크에만** 쓴다. 화면에서 코드를 직접 입력하는 칸은 없앴다(2026-09-06) — 들어가는 길은 방 목록과 초대 링크 둘뿐이다.

### 8.2 결정론적 락스텝

- 입력은 6바이트(`mx, my, aim, buttons, char`). 틱 `t` 에 샘플한 입력을 `t + delay`(2~6틱, RTT 로 결정)에 배정하고 최근 8틱을 함께 보내 손실을 흡수한다.
- 모두의 입력이 도착한 틱만 진행한다(스톨). 4인 기준 한 사람이 보내는 양은 초당 약 10KB.
- 60틱마다 상태 해시를 호스트에게 보내고, 어긋난 사람에게만 호스트가 상태 스냅샷을 보내 되돌린다(모래주머니 상태도 함께 복원).
- **이탈**: 호스트가 앞선 틱을 정해 알리고, 모두가 같은 틱에 그 사람을 제거한다. 호스트가 나가면 방이 끝난다.
- 틱 타이머는 **전용 Web Worker**. 탭이 뒤에 있어도 시뮬레이션은 계속 돈다(렌더만 멈춘다).

### 8.3 한계

- **치트 방지 불가.** 권위 서버가 없다. 친구 대전용.
- 가장 느린 회선에 모두가 맞춰진다(락스텝 특성).
- 대칭 NAT·회사망에서는 연결이 안 될 수 있다. **TURN 은 쓰지 않는다**(비용 원칙) → "폰 핫스팟으로 재시도" 안내가 최종.
- 공용 로비 방은 접속자 전원이 하나의 메시라, 동시 접속이 수십 명 규모가 되면 그쪽이 먼저 부담이 된다.

### 8.4 전적 기록 — 없앴다 (2026-09-06)

v1.0 부터 끝난 판을 브라우저에 남기고 로비 아래 "최근 전적" 으로 보여 줬는데, **가볍게 즐기는 게임이라 볼 사람이 없어 뺐다**(사용자 요청).
서버·DB 가 없으니 전적을 남길 곳이 원래 브라우저뿐이었고, 그마저 이제 남기지 않는다. 결과는 판이 끝날 때의 결과표로만 본다.

### 8.5 난입 절차 (2026-09-06 재설계)

"난입 때문에 **하던 사람이 3틱 넘게 멈추는 일이 없어야** 한다. 바로 되거나, 못 들어오거나" 가 요구다.

1. 난입자 → 호스트 `joinAsk`. **연결되는 피어마다** 보낸다(풀 메시라 피어는 한 명씩 붙고, 호스트가 첫 번째라는 보장이 없다).
   대기실 호스트는 무시하고 `room` 을 주므로(→ 대기실), 초대 링크로 게임 중인 방에 들어와도 그대로 난입이 된다.
2. 호스트는 자리를 잡아 두고 곧바로 `resume`(그 시점 판 전체)을 보낸다. 난입자는 그 판으로 세션을 열되 **관전 상태**다 —
   자기 자리는 아직 판에 없고, **모두의 락스텝도 그 자리를 기다리지 않는다**(dropped). 관전 중에는 틱당 16스텝까지 따라잡는다.
3. 난입자는 세션을 열자마자 `inputsPlease` 로 지난 입력을 받고(세션이 열리기 전에 온 패킷은 받을 곳이 없었다),
   호스트가 준 피어 목록의 **전원과 연결되면** `joinReady`.
4. 호스트는 `joinReady` 를 받았고 · 그 사람 입력 패킷이 실제로 오고 있고 · 그 사람이 판을 10틱 안까지 따라잡았을 때만
   `joinLive {p, tick: 지금+40}` 을 방송한다. 그 틱에 **모두가 같은 틱에** 자리를 채우고(`joinPlayer`) 그때부터 보통 피어처럼 기다린다.
   그 틱 전의 그 사람 입력은 **누구에게나 빈 입력**으로 덮어쓴다(`Lockstep.activate`) — 리싱크가 지난 틱을 다시 돌려도 어긋나지 않는다.
5. 8초 안에 4 가 안 되면 호스트가 `joinCancel` 로 자리를 되돌리고 `rejoinNo` 로 그 사람을 로비로 돌려보낸다. 기존 사람들은 아무것도 못 느낀다.
   앉기 전에 나가도 같은 취소다(전에는 유령이 소환되고 모두가 그 입력을 기다리다 멈췄다).
6. 평소 입력 패킷은 최근 8틱만 겹친다. 메시가 8틱 넘게 늦게 완성되는 쌍은 그 사이가 영영 비므로, 피어가 붙을 때마다
   `Lockstep.resendTo` 로 지난 입력(최대 1800틱)을 몰아 보낸다.

실측(로컬 4탭): 3번째·4번째 난입 동안 기존 사람들의 최대 틱 공백 **31~42ms**(2~2.5틱). 재설계 전 4번째 난입은 0.45초 멈췄다.

**팀전에는 난입이 없다.** 목록에서 잠그고 호스트도 거절한다. 짝이 안 맞는 채로 이어 봐야 의미가 없어서, 팀전은 **한 명만 나가도 그 자리에서 끝나고** 결과표를 띄운다
(승자는 그때까지의 팀 킬, 같으면 무승부. 다시 하기는 없다).

## 9. 소리

파일 없이 **Web Audio 로 절차 생성**한다(저작권 문제 없음).

- 효과음: 무기별 총성, 피격·헤드샷, 사망, 리스폰, 대시, 재장전, 벽 튐, 총알 막기, 모래주머니 파괴, 카운트다운, 시작·종료 화음. 듣는 위치 기준 거리 감쇠와 좌우 패닝.
- 배경음: 132 BPM 단조 추격 루프(킥·스네어·하이햇 + 16분 베이스 + 아르페지오 + 리드 + 8마디마다 상승음). 교전이 벌어지면 레이어가 두꺼워진다.
- `N` 키 또는 화면 오른쪽 위 버튼으로 음소거(브라우저에 기억).

## 10. 결정론 규칙 (반드시 지킬 것)

`src/core/` 는 두 브라우저가 같은 입력으로 **완전히 같은 결과**를 내야 한다.

1. `Math.sin/cos/atan2/random`, `Date.now`, `performance.now` 금지. 삼각함수는 `fixedmath.ts` 의 1024단계 테이블(1/65536 단위로 반올림), 난수는 `rng.ts`(mulberry32).
2. 렌더·DOM·오디오를 import 하지 않는다.
3. 플레이어의 의사(캐릭터 교체 등)는 반드시 `Input` 에 실어 보낸다. 렌더 쪽에서 직접 상태를 바꾸지 않는다.
4. 맵은 시드로 생성한다. 모래주머니가 부서지면 sim 이 `map.tiles` 를 바꾸지만, 정본은 `GameState.sandbags` 이고 `createState`/`syncSandbags` 로 언제나 복원된다.
5. 부동소수 연산 순서를 바꾸지 않는다(반복 순서도 상태의 일부다).

검증: `tests/determinism.test.ts` 가 같은 시드로 두 번 돌려 60틱마다의 해시를 비교한다.

| 4인 · 4배 맵 · 봇 4명 (혼자 하기 최악) | 0.023 ~ 0.033ms |
| 4인 대전 (봇 없음) | 0.001ms |

## 12. 밸런스 방법론

`tools/balance.ts` 가 봇끼리 **1:1 전 조합 528판**과 **4인 개인전 72판**을 돌려 캐릭터별 승률·K/D·주고받은 피해, 무기별 명중률·헤드샷 비율·거리 구간별 명중을 표로 뽑는다.

```bash
npx vite-node tools/balance.ts       # 1:1 전 조합
npx vite-node tools/balance.ts ffa   # 4인 개인전
```

2026-09-05 기준 1:1 승률은 **42.0 ~ 56.8%** 밴드. `tests/balance.test.ts` 가 매 테스트마다 20~80% 밴드와 모든 무기의 유효성을 검사한다.

봇은 **의도적으로 막기를 유지하는 플레이를 못 한다.** 그래서 후라이팬처럼 사람이 쓸 때만 강한 것은 이 표에 안 잡힌다.
`tools/melee.ts` 가 그 구멍을 메운다 — 승빠덕이 구르지 않고 정면으로 버티는 최악의 대치를 10판 돌린다.

봇 실력은 사람과 다르므로 이 수치는 "어느 쪽이 크게 기울었는가"를 보는 용도다. 사람이 직접 해 본 체감이 최종 기준이다.

**봇 조준 (2026-09-05 하향).** 봇이 사람보다 잘 맞혔다(사용자). 각도 오차·손떨림을 키우고 예측 사격을 줄였다.

| 난이도 | 각도 오차 | 손떨림 | 예측 | 회전 |
|---|---|---|---|---|
| 쉬움 | 18° → **22°** | 9° → **11°** | 0 | 0.07 |
| 보통 | 11° → **14°** | 6° → **8°** | 0.2 → **0.15** | 0.13 → **0.12** |
| 어려움 | 5.5° → **8°** | 3° → **4.5°** | 0.6 → **0.5** | 0.3 → **0.26** |

봇의 조준점에는 **거리 오차 ±6%** 도 준다(`BOT_AIM.depthErr`). 사람은 커서 깊이가 정확하지만 봇에게까지 그러면 각도 오차가 작을 때마다
"커서가 상대 위"(= 맞으면 헤드샷)가 돼 소총 헤드샷이 39% 까지 갔다. 0 → 39%, 0.06 → 약 12%, 0.08 → 9.5%, 0.25 → 3.6%. 사람이 확정한 11~14% 근처로 맞췄다.

그 결과 봇 표는 **정밀 무기를 낮게 잰다**: 어려움 봇 명중률이 저격 27.5% → 23.5%, 소총 25.5% → 22.8% 로 내려가고,
5시드 밴드가 43.0~60.0% 에서 **35.0~63.0%** 로 벌어졌다(저격 둘이 35~38%, 기관총·산탄·SMG 가 57~63%).
이건 봇이 저격을 못 쓰게 된 것이지 저격이 약해진 게 아니다. 사람은 봇보다 잘 겨누므로 **저격 하향은 사람 체감으로 판단**한다.

## 14. 빌드와 배포

```bash
npm run dev      # 개발 서버
npm test         # vitest (결정론·카메라·성능·밸런스)
npm run build    # tsc --noEmit + vite build → dist/
```

`main` 에 push 하면 GitHub Actions 가 테스트·빌드 후 GitHub Pages 에 배포한다(`.github/workflows/deploy.yml`).

진입점은 `index.html` 하나다(트레일러용 프리뷰 페이지는 v1.0 에서 삭제했다).
개발 서버에만 스크린샷 저장 엔드포인트 `POST /__shot` 이 있다(`vite.config.ts` 의 `shotEndpoint`, `apply: 'serve'`).
주소 뒤에 `?shot=1` 을 붙이면 WebGL 캔버스 버퍼가 보존되어 `canvas.gl` + `canvas.hud` 를 합쳐 저장할 수 있다. 배포물에는 없다.
