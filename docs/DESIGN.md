## 0. 한 줄 결론

**가능하다.** 브라우저 WebRTC DataChannel로 1:1 실시간 대전은 충분히 구현되며, 게임 클라이언트 전체를 GitHub Pages에 올릴 수 있다.
단, "서버 0"에는 한 가지 예외가 있다. WebRTC는 연결을 맺을 때 **시그널링(주소 교환)** 이 필요한데, 이것은 직접 서버를 띄우지 않고 공개 인프라(Trystero)나 수동 복붙으로 해결한다. 아래 1장에서 설명.

## 1. 가능성 검토

### 1.1 되는 것

| 요구사항 | 가능 여부 | 방법 |
|---|---|---|
| 서버 없는 1:1 실시간 대전 | ✅ | WebRTC `RTCDataChannel` (P2P, UDP 기반, 국내 RTT 20~60ms) |
| GitHub에 올려서 서비스 | ✅ | GitHub Pages 정적 호스팅 (HTTPS 기본 제공, WebRTC에 필요) |
| 쿼터뷰 슈팅 | ✅ | Phaser 3 (2D WebGL) + 탑다운 3/4 시점 스프라이트 |
| 작고 말랑한 캐릭터 | ✅ | 스프라이트 squash & stretch 트윈, 피격 젤리 흔들림 |
| 덕코프식 시스템 (부위 피해, 아머, ADS) | ✅ | 자체 시뮬레이션 레이어에서 구현 (3장) |

### 1.2 "서버 없음"의 정확한 의미

WebRTC는 두 브라우저가 서로의 네트워크 주소(SDP/ICE)를 한 번 교환해야 연결된다. 이 교환 통로가 시그널링이다. 선택지 3가지:

| 방식 | 내가 운영하는 서버 | UX | 비고 |
|---|---|---|---|
| **A. Trystero (권장)** | 없음 | 방 코드 입력만 | 공개 Nostr 릴레이 / BitTorrent 트래커 / MQTT 브로커를 시그널링 통로로 사용. 라이브러리 하나로 끝. |
| B. 수동 복붙 | 없음 | 나쁨 (긴 문자열 2번 교환) | A가 실패할 때 폴백으로 유지 |
| C. PeerJS 공개 클라우드 / Firebase 무료 티어 | 없음(남의 서버) | 좋음 | 외부 서비스 의존, PeerJS 공개 서버는 가끔 다운 |

**권장: A를 기본, B를 폴백.** 둘 다 GitHub Pages 정적 파일만으로 동작한다.

### 1.3 NAT 통과 (STUN / TURN)

- **STUN**: 무료 (`stun:stun.l.google.com:19302`). 대부분의 가정용 공유기에서 이것만으로 P2P 연결됨.
- **TURN**: 대칭형 NAT, 일부 회사망, 모바일 LTE에서는 STUN만으로 실패 (경험적으로 10~20%). TURN 릴레이가 필요하며 이것은 "서버"다. 선택지:
  - Cloudflare Realtime TURN 무료 티어 (월 1TB) — 자격증명을 프론트에 노출하면 안 되므로 단기 토큰 발급이 필요 → 사실상 작은 서버리스 함수 필요.
  - metered.ca / Open Relay 무료 티어 — 자격증명이 공개용이라 정적 사이트에 그냥 넣어도 됨. 대역폭 제한 있음.
  - **MVP 결정: TURN 없이 시작.** 연결 실패 시 "핫스팟 등 다른 네트워크로 재시도" 안내 문구를 띄운다. 친구끼리 하는 게임이면 이 정도로 충분하다. 필요해지면 Open Relay를 추가.

### 1.4 P2P 구조의 한계 (미리 받아들일 것)

- **치트 방지 불가.** 권위 있는 서버가 없으므로 상대가 클라이언트를 조작하면 막을 수 없다. 친구 대전용이므로 무시한다.
- **매치메이킹 없음.** 방 코드(또는 링크)를 직접 공유한다. `https://<id>.github.io/<repo>/#room=ABCD` 형태.
- **브라우저 탭이 백그라운드로 가면** `requestAnimationFrame`이 멈춘다. 틱 루프는 `setTimeout`/Worker 기반으로 돌리거나, 포커스를 잃으면 일시정지 처리한다.
- **네트워크 품질이 게임 품질.** 한 쪽 회선이 나쁘면 둘 다 영향을 받는다 (락스텝 특성). 롤백 넷코드로 완화 가능 (4장).

### 1.5 법적 / 초상권

배도라지 멤버는 실존 인물이다. 비상업 팬게임이라도 다음을 지킨다:

- 실명 대신 **활동명 또는 패러디 명칭** 사용 (예: "침착덕", "철면덕"). 캐릭터는 원본 초상이 아니라 오리 형태에 특징 소품(안경, 모자, 수염)만 얹는다.
- 첫 화면에 "비공식 팬 프로젝트, 비상업, 문의 시 즉시 삭제" 고지.
- 멤버 비하로 읽힐 수 있는 스킬/대사는 넣지 않는다. 크루 내부 밈이라도 외부에서 보면 다를 수 있다.
- 광고, 후원, 굿즈 등 수익화는 하지 않는다.

## 2. 게임 컨셉

### 2.1 정체성

- **제목(가칭)**: 배도라지 덕 / Escape from Bedorage
- **장르**: 1:1 쿼터뷰 슈터. 덕코프의 손맛(조준·지향사격, 부위 피해, 아머 관통, 현장 루팅)을 2인 대전에 압축.
- **세션 길이**: 한 판 3~5분. 방 코드 공유 → 캐릭터 선택 → 대전 → 결과 → 리매치.
- **조작**: 키보드+마우스. WASD 이동, 마우스 조준, 좌클릭 사격, 우클릭 조준(ADS), Space 대시, R 재장전, E 상호작용, 1~3 힐템, Q 무기 교체.

### 2.2 모드

1. **듀얼 (데스매치)** — 3킬 선취. 라운드 사이 5초 리스폰. 장비는 캐릭터 기본 장비.
2. **탈출 결투 (Extraction Duel)** — 제한시간 3분. 맵 곳곳의 상자를 열어 무기·아머·힐템을 줍고, 상대를 처치하거나 탈출구에 먼저 도달하면 승리. 시간 종료 시 가방 가치 합계로 판정. 덕코프의 "루팅 → 탈출" 루프를 대전용으로 재해석한 핵심 모드.

MVP는 1번만, 2번은 M3에서 추가.

### 2.3 캐릭터: 배도라지 12인 → 덕

공통 원칙: **베이스 덕 스프라이트 1종 + 액세서리 레이어**로 12명을 만든다. 얼굴/몸통은 동일, 안경·모자·머리·수염·색상만 레이어로 얹는다. 아트 제작 비용을 1/10로 줄이는 핵심 결정.

각 캐릭터 = 스탯 편차(체력·속도) + 패시브 1개 + 시그니처 장비 1개. 아래는 초안이며 밸런스는 플레이테스트로 조정.

| 우선순위 | 캐릭터 | 컨셉 근거 | 스탯 성향 | 패시브(초안) | 시그니처(초안) |
|---|---|---|---|---|---|
| MVP | 침착덕 (침착맨) | 크루의 중심, "침착" | 밸런스 | **침착**: 피격 중에도 조준 흔들림 없음 | 펜 투척 (관통 1, 재사용 쿨다운) |
| MVP | 주펄덕 (주펄) | 침펄 콤비 | 밸런스 | **토론**: 근접 시 상대 탄퍼짐 증가 | 만화책 방패 (전방 피해 50% 감소, 이동 감소) |
| MVP | 철면덕 (철면수심, 배도라지장) | 차돌야차 | 체력↑ 속도↓ | **차돌**: 아머 내구도 +50% | 산탄총 |
| MVP | 매직덕 (매직박) | 치과의사, 창설 멤버 | 밸런스 | **진료**: 힐 아이템 사용 속도 2배 | 강화 메드킷 |
| 2차 | 단군덕 (단군) | 게임 캐스터 | 속도↑ | **중계**: 일정 주기로 상대 위치 핑 | 마이크 (소리 웨이브, 짧은 사거리 광역) |
| 2차 | 우원덕 (우원박) | 배우 | 속도↑ | **연기**: 대시 직후 0.2초 무적 | 권총 2정 |
| 2차 | 기열덕 (기열킹) | 뇌절 | 공격↑ | **뇌절**: 연속 명중 시 데미지 증가, 빗나가면 초기화 | SMG |
| 2차 | 풍월덕 (풍월량) | 바람물질 | 속도↑↑ 체력↓ | **바람**: 대시 쿨다운 절반 | 소총 |
| 3차 | 옥냥덕 (옥냥이) | 실질 리더 | 밸런스 | **리더십**: 첫 킬 시 아머 회복 | 저격 |
| 3차 | 통닭덕 (통닭천사) | 치킨 | 체력↑ | **치킨**: 킬 시 치킨(힐템) 드롭 | 산탄총 |
| 3차 | 갓보기덕 (갓보기) | 보기 | 밸런스 | **시야**: 카메라 시야 범위 +20% | 소총 |
| 3차 | 승우덕 (승우아빠) | 요리 | 밸런스 | **요리**: 힐템 효과 +30% | 프라이팬 (근접, 투사체 반사) |

MVP는 위 4명. 침펄 콤비 + 다라이나믹 듀오(매직박·철면수심)로 크루 대표 조합을 커버한다.

### 2.4 말랑함 표현

- 걷기: 몸통 Y 스케일 0.95↔1.05 바운스 (8Hz).
- 피격: 흰색 플래시 1프레임 + X/Y 스케일 반대 방향 튕김 (1.2/0.8 → 0.9/1.1 → 1.0) 120ms.
- 대시: 진행 방향으로 늘어남 (1.3/0.8).
- 사망: 납작해지며 (1.4/0.3) 튕겨서 사라짐.
- 착지/정지: 작은 squash.

## 3. 게임 시스템 (덕코프 차용)

### 3.1 체력과 부위 피해

- HP 100 단일 풀. 쿼터뷰에서 정확한 부위 판정은 무리이므로 덕코프처럼 **확률 가중 부위 판정**을 쓴다.
- 명중 시 부위 추첨: 머리 / 몸통 / 다리. 확률은 사격 방식과 거리로 결정.

| 조건 | 머리 | 몸통 | 다리 |
|---|---|---|---|
| ADS, 근거리(<200px) | 25% | 55% | 20% |
| ADS, 원거리 | 15% | 60% | 25% |
| 지향사격 | 8% | 62% | 30% |

- 배율: 머리 ×2.0, 몸통 ×1.0, 다리 ×0.6 + **다리 부상** 상태(이동 30% 감소, 붕대로 해제).
- 몸통 피격 3회 누적 시 **출혈** (초당 1 HP, 붕대로 해제).

### 3.2 아머

- 클래스 1~3, 내구도 보유. 캐릭터 기본 아머는 클래스 1, 맵 상자에서 2~3 획득.
- 판정: `탄 관통력 >= 아머 클래스` 이면 피해 100% 통과 + 내구도 -피해량. 아니면 피해 40% + 내구도 -피해량. 내구도 0이면 아머 소멸.
- 머리 부위는 아머 미적용 (헬멧은 후순위 확장).

### 3.3 무기 (초기 5종)

| 무기 | 피해 | 연사(RPM) | 탄창 | 재장전 | 탄퍼짐 hip/ADS | 탄속(px/s) | 관통 |
|---|---|---|---|---|---|---|---|
| 권총 | 22 | 300 | 12 | 1.2s | 8° / 3° | 900 | 1 |
| SMG | 16 | 750 | 30 | 1.8s | 10° / 5° | 850 | 1 |
| 소총 | 30 | 500 | 30 | 2.2s | 7° / 2° | 1100 | 2 |
| 산탄총 | 12×8 | 70 | 6 | 0.6s/발 | 18° / 12° | 700 | 1 |
| 저격 | 90 | 40 | 5 | 3.0s | 12° / 0.5° | 1600 | 3 |

- 탄은 **투사체**(레이캐스트 아님). 벽에 막히고, 시각적으로 날아간다. 덕코프 느낌의 핵심.
- ADS(우클릭 홀드): 이동 속도 60%, 탄퍼짐 ADS 값, 카메라가 조준 방향으로 최대 120px 이동(덕코프 특징).
- 반동: 연사 시 탄퍼짐이 발당 +1.5°, 사격 중지 시 초당 -10°.

### 3.4 루팅과 인벤토리 (탈출 결투 모드)

- 인벤토리 슬롯 고정: 주무기 1, 보조무기 1, 아머 1, 힐템 3, 가방(가치 아이템) 5.
- 상자: 맵에 8~12개, 상호작용 1.5초 (게이지). 내용은 시드 기반 랜덤 → 양쪽 동일.
- 힐템: 붕대(출혈·다리부상 해제, 2초), 메드킷(+50 HP, 4초), 치킨(+25 HP, 1.5초, 이동 가능).
- 탈출구: 맵 양 끝 2곳, 진입 후 5초 유지하면 탈출. 상대에게 탈출 시도 알림 표시.

### 3.5 맵

- 32px 타일, Tiled 에디터로 제작, JSON 로드.
- 첫 맵 "스튜디오": 40×30 타일 (1280×960 월드). 카메라 640×480 → 2배 확대. 중앙 오픈 공간 + 양쪽 방 구조 + 엄폐물(책상, 소파, 촬영장비).
- 벽은 탄 차단, 낮은 엄폐물(책상)은 ADS 시 넘어 쏘기 가능.
- 시야 제한(벽 뒤 안 보임)은 후순위. MVP는 맵 전체 노출.

## 4. 기술 아키텍처

### 4.1 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 언어 | TypeScript | 결정론적 시뮬레이션에 타입 필수 |
| 번들러 | Vite | GitHub Pages `base` 설정 간단, 빠름 |
| 렌더링 | **Phaser 3** | 2D WebGL, 타일맵·입력·오디오·트윈 내장. 쿼터뷰는 스프라이트 Y-정렬로 표현 |
| 물리 | **자체 구현** (Phaser Arcade 미사용) | 넷코드용 결정론 확보. 원 vs AABB 충돌만 있으면 됨 |
| 네트워크 | WebRTC DataChannel + **Trystero** (시그널링) | 서버 없음 |
| 맵 도구 | Tiled | 무료, Phaser 호환 JSON |
| 아트 도구 | Aseprite (유료 $20) 또는 LibreSprite/Piskel (무료) | 픽셀아트 + 레이어 |
| 오디오 | Phaser Audio (Web Audio) | 별도 라이브러리 불필요 |
| UI(로비/HUD) | 순수 DOM + CSS | 게임 캔버스 위 오버레이. 프레임워크 불필요 |
| 배포 | GitHub Actions → GitHub Pages | push 하면 자동 배포 |

**대안 검토**: Godot 4 웹 내보내기(WebRTC 내장)도 가능하지만 빌드 30MB+, 넷코드 세밀 제어가 어렵고 GitHub Pages에서 SharedArrayBuffer 헤더 이슈가 있어 제외. Three.js 3D는 덕코프와 더 닮지만 에셋 제작 비용이 5배 이상이라 2D로 결정.

### 4.2 레이어 구조

```
┌──────────────── Browser A (GitHub Pages) ────────────────┐
│  ui/        로비 · 캐릭터 선택 · HUD · 결과      (DOM)      │
│  render/    Phaser Scene — sim 상태를 읽어 그리기만 함      │
│  core/      결정론적 시뮬레이션 (순수 TS, 렌더 무관)         │
│             입력 → step() → 상태.  Math.random/sin 금지     │
│  net/       Trystero 시그널링 · DataChannel · 락스텝 · 리싱크│
└───────────────────────────┬──────────────────────────────┘
                            │ RTCDataChannel (입력 패킷, 60Hz)
┌───────────────────────────┴──────────────────────────────┐
│                       Browser B (동일 코드)                 │
└──────────────────────────────────────────────────────────┘
        시그널링: Trystero → 공개 Nostr 릴레이 / BT 트래커
        NAT:     STUN (Google) · TURN (없음, 선택적 추가)
```

핵심 규칙: **core/ 는 Phaser를 import 하지 않는다.** 그래야 두 브라우저에서 같은 입력으로 같은 결과가 나오고, 헤드리스 테스트가 가능하다.

### 4.3 결정론 규칙 (core/ 작성 규칙)

두 브라우저가 같은 입력으로 비트 단위로 같은 상태를 만들어야 한다.

- 고정 틱: **60Hz (16.667ms)**. 렌더 프레임과 분리.
- 부동소수점 `+ - * / sqrt`는 IEEE754로 엔진 간 동일 → 사용 가능.
- **금지**: `Math.sin/cos/atan2/pow/exp/log`, `Math.random`, `Date.now`, `performance.now`, 객체 키 순회 순서에 의존하는 로직.
- 삼각함수는 **1024 단계 룩업 테이블** (`fixedmath.ts`). 조준각은 입력 패킷에서 이미 0~1023 정수로 양자화됨.
- 난수는 시드 PRNG (`mulberry32`). 시드는 호스트가 방 생성 시 정하고 컨트롤 채널로 공유.
- 엔티티는 ID 오름차순 배열로 순회. `Map`/`Set` 순회는 삽입 순서가 양쪽에서 같을 때만.
- 상태는 **직렬화 가능한 plain 객체/TypedArray**. 롤백 시 스냅샷 복사가 싸야 한다.
- 매 60틱마다 상태 해시(FNV-1a)를 교환해 디싱크 감지.

### 4.4 넷코드: 결정론적 락스텝 → 롤백

| | 락스텝 (MVP) | 롤백 (M6) | 호스트 권위형 (대안) |
|---|---|---|---|
| 구현량 | 적음 (~150줄) | 많음 | 중간 |
| 공정성 | 대칭 | 대칭 | 호스트 유리 |
| 체감 입력지연 | RTT/2 + 여유 (국내 3~4틱 ≈ 50~66ms) | 0 (예측) | 게스트만 지연 |
| 결정론 필요 | 필수 | 필수 | 불필요 |
| 상대 랙 영향 | 둘 다 멈춤 | 예측으로 흡수 | 게스트만 |

**결정: 락스텝으로 시작한다.** 이유: 2인 게임에서 가장 코드가 적고, 대칭적이며, 결정론 sim을 갖춰 두면 롤백으로 무중단 업그레이드 가능. 호스트 권위형은 결정론이 필요 없어 편하지만, 1:1 대전에서 호스트 유리는 받아들이기 어렵고 예측·보정·랙보상 코드가 결국 더 많아진다.

락스텝 루프 (의사 코드):

```ts
const DELAY = adaptiveDelay(rtt)          // 2~5틱, RTT 기준 자동
let acc = 0
function frame(dt) {
  acc += dt
  while (acc >= TICK_MS) {
    const t = sim.tick
    local.set(t + DELAY, sampleInput())    // 지금 입력은 미래 틱에 적용
    sendInputs(t + DELAY)                  // 최근 8틱 입력을 한 패킷에 중복 전송 (패킷 손실 흡수)
    if (!remote.has(t)) break              // 상대 입력 도착 전이면 대기 (스톨)
    sim.step(local.get(t), remote.get(t))
    if (t % 60 === 0) exchangeHash(sim.hash())
    acc -= TICK_MS
  }
  render.interpolate(sim.prev, sim.curr, acc / TICK_MS)
}
```

디싱크 처리: 해시 불일치 → 방 생성자(호스트 역할은 리싱크에만 사용)가 전체 상태 스냅샷을 컨트롤 채널로 전송 → 상대가 덮어쓰기 → 계속 진행. 플레이어에게는 짧은 "동기화 중" 표시.

롤백 업그레이드(M6): 상대 입력이 아직 안 왔으면 마지막 입력을 반복한다고 **예측**하고 진행. 실제 입력이 늦게 도착하면 해당 틱 스냅샷으로 되돌려 재시뮬레이션. sim 상태가 TypedArray라면 스냅샷 복사는 수십 µs.

### 4.5 프로토콜

DataChannel 2개:

| 채널 | 설정 | 용도 |
|---|---|---|
| `input` | `ordered: false, maxRetransmits: 0` | 매 틱 입력 패킷 (재전송 없음, 중복 전송으로 손실 흡수) |
| `control` | `ordered: true` (기본, 신뢰) | 핸드셰이크, 시드, 캐릭터 선택, 상태 해시, 리싱크 스냅샷, 채팅, 리매치 |

Trystero는 시그널링 후 `room.getPeers()`로 `RTCPeerConnection`을 내주므로, 거기서 직접 `createDataChannel`로 두 채널을 만든다.

입력 패킷 (바이너리, `DataView`):

```
u32 latestTick
u8  count (1~8)
반복 count회, 최신 → 과거 순:
  i8  moveX  (-1/0/1)
  i8  moveY  (-1/0/1)
  u16 aim    (0..1023, 1024단계 각도)
  u8  buttons bit0 fire · bit1 ads · bit2 reload · bit3 dash
              bit4 interact · bit5 heal1 · bit6 heal2 · bit7 swap
```

패킷 ≈ 5 + 5×8 = 45바이트, 초당 60개 → **약 2.7KB/s**. 무시할 수준.

### 4.6 시그널링 흐름 (Trystero)

```ts
import { joinRoom } from 'trystero'          // 기본 전략: Nostr 릴레이
const room = joinRoom(
  { appId: 'bedorage-duck', rtcConfig: { iceServers: [{ urls: 'stun:stun.l.google.com:19302' }] } },
  roomCode,                                  // 6자리 코드, URL 해시에서 읽음
)
room.onPeerJoin(peerId => {
  const pc = room.getPeers()[peerId]        // RTCPeerConnection
  // 방 생성자가 input/control DataChannel 생성, 상대는 ondatachannel로 수신
})
```

- 방 코드는 `crypto.getRandomValues`로 6자 생성. 같은 appId+roomCode면 공개 릴레이에서 만난다. `password` 옵션으로 시그널링 암호화.
- 방 생성자 = 시드 결정 + 리싱크 스냅샷 송신자. 그 외 게임 로직은 완전 대칭.
- 15초 안에 연결 안 되면 수동 복붙 모드(offer/answer 텍스트)로 폴백 UI 제공.

### 4.7 렌더링

- Phaser Scene은 매 프레임 `sim.prev`, `sim.curr` 사이를 보간해 그린다 (sim 60Hz, 디스플레이 60~144Hz 대응).
- 쿼터뷰 깊이: 모든 스프라이트 `depth = y`. 벽/가구는 발 위치 기준.
- 캐릭터 = 컨테이너: [그림자] [몸통(액세서리 레이어)] [무기(조준 방향 회전)]. 몸통은 좌/우 플립만, 무기만 360° 회전 → 스프라이트 수 최소화.
- 카메라: 플레이어 + ADS 시 조준 방향 오프셋, 부드러운 lerp.
- 총구 화염, 탄피, 피격 파티클, 화면 흔들림은 렌더 전용 (sim 상태 아님).

### 7.3 결정이 필요한 것 (현재 가정)

| 2D vs 3D | 2D 픽셀 (Phaser) | 3D면 Three.js + 로우폴리, 에셋 비용 5배 |
| 해상도 | 640×480 논리, 2배 확대 | 픽셀아트 크기에 맞춰 조정 |
| 실명 표기 | 활동명 변형("침착덕") | 원본 활동명 그대로 쓰려면 멤버 측 확인 권장 |
| 플랫폼 | 데스크톱 키보드+마우스 | 모바일은 가상 조이스틱 + 자동조준 필요, 별도 마일스톤 |
| TURN | 없음 | 연결 실패율이 높으면 Open Relay 추가 |

## 8. 리스크와 대응

| 리스크 | 확률 | 대응 |
|---|---|---|
| NAT 통과 실패로 연결 안 됨 | 중 (10~20%) | 실패 안내 + 수동 폴백 + 필요 시 TURN |
| 디싱크 (두 화면이 달라짐) | 중 (개발 초기) | 4.3 규칙 준수, 해시 검사, 리싱크, 입력 재생 테스트 |
| 상대 회선 불안정 → 게임 멈칫 | 중 | 적응형 입력 지연, 8틱 중복 전송, M6 롤백 |
| 아트 제작량 폭발 | 높음 | 베이스+액세서리 레이어, MVP 4인, 무기는 코드 회전 |
| 공개 시그널링 릴레이 다운 | 낮음 | Trystero 전략 2개(Nostr+Torrent) 동시 시도, 수동 폴백 |
| 초상권 문제 제기 | 낮음 | 비상업 고지, 패러디 명칭, 즉시 삭제 정책 |
| 탭 백그라운드 시 틱 정지 | 확실 | Worker 타이머 또는 포커스 잃으면 일시정지 협의 |
